# Universal Embedded Model Runtime
## 开发计划

依据：《Universal Embedded Model Runtime：V0 架构总案（修订版）》（下称"总案"）。

> **计划性质**：范围一次给全，不设 P0/P1 分期。里程碑只反映**依赖关系与施工次序**，不反映范围裁剪。每个里程碑的完成标准统一锚定在 Conformance Suite 上。

---

# 1. 交付定义

最终交付物是一个可随宿主分发的运行时组件，包含：

```text
├── runtime core（Rust，含七大道具契约实现）
├── 四协议 Adapter + 各自 Conformance fixtures
├── Model Intelligence（Registry / Resolver / Evidence / Probe）
├── Catalog Builder（CI 流水线 + Bundled Catalog 产物）
├── Stable C ABI + 绑定生成 + 示例宿主
├── UISpec 契约 + 参考实现 UI
├── 离线安装包（三平台）
└── 宿主集成文档
```

整体完成的定义（v1.0 DoD）：

```text
1. 七大契约全部冻结并发布（总案 §41）
2. 四协议 conformance 全绿
3. 全新机器离线首启：配置 Provider → 发现模型 → 完成一次流式调用
4. ABI 握手、拉取式流、取消、partial() 在 C 示例宿主上验证通过
5. Bundled Catalog 可复现构建且许可证清单完整
6. 宿主集成文档覆盖 Rust / C / Python 三种接入方式
```

# 2. 工程总原则

从总案铁律直接推导的工程约束：

```text
├── 契约先行：任何代码先有契约定义与 fixtures，再写实现
├── 唯一门票：Adapter / Core 行为变更必须 conformance 全绿
├── 契约变更必须走评审 + schema 更新 + fixtures 同步，
│   不允许"代码先行、契约后补"
├── fixtures 一律脱敏：不得含真实 API Key、用户数据、私有端点
├── core 禁止 panic：unwrap / expect 仅限测试代码
├── unsafe 仅允许出现在 runtime-ffi 层
├── Provider 类型（AnthropicMessage / GeminiPart ...）不得进入 core 编译单元
└── 每个里程碑结束输出一次演示（fake provider 驱动，不依赖真实网络）
```

# 5. 里程碑详单

## M0 契约冻结

目标：七大契约从条文变成可编译、可校验的定义。总案要求"冻结后再编码"，本里程碑就是冻结动作本身。

工作项：

```text
├── runtime-core 全部类型：GenerateRequest / Message / Content /
│   Tool / ToolChoice / ReasoningConfig / GenerationConfig /
│   ResponseFormat / CachingConfig / GenerateResponse / StopReason /
│   ModelEvent（sequence / block_id / call_id）/ Invocation + partial() /
│   ModelError + retryable / Usage
├── runtime-model 全部类型：ModelIdentity / Deployment / ModelInfo /
│   CapabilityRecord / CompatibilityProfile / Evidence / Pricing
├── Resolver 算法定稿：字段级优先级表 + 冲突标记（总案 §13）
├── FFI ABI 草案：句柄模型、错误码表、runtime_stream_next 签名、
│   版本握手（总案 §50）
├── UISpec schema 草案：settings_schema / apply / discovery_session /
│   strings 的数据结构（总案 §38.1）
├── 版本化策略文档：Runtime semver / Catalog format_version / ABI major
└── ABI 流式 spike：最小 C 程序经 ABI 从 fake provider 拉取事件流
    （提前排雷拉取式 ABI 的全部工程问题）
```

交付物：契约文档 + JSON Schema（由 Rust 类型生成，Rust 为唯一真值）+ spike 演示。

完成标准：

```text
├── 七契约评审通过，打 contract-v1 tag
├── Rust 类型 / JSON Schema / 文档三者一致（生成式保证）
└── spike：C 程序收到流事件、触发取消、握手拒绝错误主版本
```

预估：2–3 人周。

## M1 Core 骨架与 Conformance 基建

目标：与协议无关的全部 Core 行为完成，且验证基建就位。此后所有 Adapter 都在"有考场"的环境下开发。

工作项：

```text
├── Invocation 生命周期 + 终结事件保证（§23.1）+ 取消语义
├── Stream 聚合引擎：全局单调 sequence、block 归属、Delta append-only 重组
├── 四段超时（connect / first_token / idle / total）+ Retry + Retry-After
│   + 安全重放判断（部分输出不盲重）
├── partial() 部分结果保留（§25.1）
├── ModelError 框架 + raw_context / 日志强制脱敏
├── CredentialStore trait + 测试用内存实现
│   （OS 实现在 M9 完成，回退链一并实现）
└── runtime-conformance：
    ├── fixture 文件格式（请求 / 响应 / SSE 序列 / 错误注入）
    ├── fake-provider：可脚本化——延迟、断流、畸形 SSE、错误码、乱序 delta
    └── 断言库：事件序列、终结保证、重组正确性、重放行为
```

完成标准：

```text
├── fake-provider 驱动以下场景全绿：
│   ├── 正常流式重组（含并行 ToolCall 归属）
│   ├── 中途取消 → Cancelled + partial() 可取回
│   ├── 四段超时各自触发 → Failed + partial() 可取回
│   ├── 断流 / 畸形 SSE → 合成 Failed（终结保证）
│   └── RateLimited → 按 Retry-After 退避重试；部分输出后不盲重
└── runtime-core 行覆盖 ≥ 85%
```

预估：3–4 人周。

```text
├── CompatibilityProfile 字段填充与 emulated 标记
└── fixtures：录制并脱敏真实流量 + 手工边界用例（空响应、截断、乱序）
```

完成标准：

```text

├── 真实冒烟（人工门禁）：DeepSeek 官方端点 + 任一第三方兼容网关
└── 一个 Custom Provider（openai_chat）从配置到流式调用全流程演示
```

# 6. 并行度与人力安排

按 3 名熟练 Rust 工程师设计；2 人时关键路径不变、周期拉长约 1.5 倍。

```text
工程师 A（协议链）：M0 → M1 → M2 → M3 → M4 → M5
```

# 7. 测试与质量策略

```text
层级：
├── 单元测试：Resolver 仲裁 / 重组 / 超时 / 重放（core 行覆盖 ≥ 85%）
├── Conformance：协议 Adapter 的唯一验收门禁（§52 清单）
├── ABI 测试：C 层拉取 / 取消 / 握手 / 错误码
├── 集成测试：fake-provider 全流程（配置 → 发现 → 调用 → 取消）
└── 真实冒烟：人工门禁，每个协议里程碑一次，不计入 CI

CI 门禁：
├── fmt + clippy（deny warnings）
├── 全量测试 + 对应 conformance
├── core 行覆盖 ≥ 85%
├── fixtures 脱敏检查（扫描 key 模式 / 私有域名）
└── Provider 类型泄漏检查（core 编译单元 grep 门禁）

录制规则：
├── 本地代理录制真实流量 → 自动脱敏 → 人工复核 → 归档 golden
└── 禁止 CI 直接消耗真实 Token（真实冒烟除外，人工触发）
```

# 10. 契约变更规则

开发期内发现契约缺陷时的处理流程：

```text
提案（写明影响面：哪些契约 / 哪些 fixtures / 哪些已写代码）
        ↓
评审（三人 + 总案对照）
        ↓
├── 兼容追加 → contract-v1.x，fixtures 增补
└── 破坏性变更 → 发布前允许一次性修订：
    更新契约文档 + schema + 全部 fixtures 同步 + 重打 tag
    （v1.0 尚未对外发布，是唯一允许破坏性修订的窗口期）
        ↓
不允许：代码先行、契约后补；先改实现、后改 fixtures
```

v1.0 发布之后，任何 Canonical 契约的破坏性变更 = 主版本递增（总案 §51）。
